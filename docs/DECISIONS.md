## Phase 5 outcome decisions

- **ADR-039:** Retain the validation-selected LR artifact (`oilwell-binary-phase5-c4e1835a82620306778a`) and exact threshold after its one-time diagnostic test failed normal-time alarm control. Monitoring acceptance is rejected; no post-test replacement, refit or threshold adjustment. Selection completion is distinct from detector acceptance.
- **ADR-040:** Disclose the discovered CatBoost inference-thread deviation without rewriting frozen code or rerunning benchmarks after test. Its native prediction default is not guaranteed single-thread; all fits were single-thread, timing did not select the model and selected LR inference is unaffected.

## Configuration evidence

Phase 5 decisions (2026-11-10), recorded before candidate fitting:

- **ADR-036:** User-authorized eight fixed CatBoost/XGBoost configurations and two saved learned incumbents, identical frozen features/groups, seed 42, CPU thread 1. Select validation recall under a 5% exact normal-time alarm-occupancy cap, then AP and deterministic ties. This cap is an exploratory engineering constraint, not an operational acceptance requirement; all trials remain visible.
- **ADR-037:** Defer calibration, multiclass fitting and deep models because independent support/sequence-benefit evidence is inadequate. Preserve uncalibrated score semantics, evaluate probability losses only where meaningful, and report synthetic-origin metrics as unsupported rather than manufacturing a domain comparison.
- **ADR-038:** Lock selection/code/bundle/provenance before a root-released single test inference. Persist exclusive access journal before any test read, refuse repeats even after partial failure, and independently audit saved outputs without re-inference. Existing test is EDA-exposed diagnostic; no production/generalization acceptance follows from it.

The original project configuration already used the current `agents.enabled` and `agents.max_concurrent_threads_per_session` keys. It was retained and augmented with `features.multi_agent=true`, rather than replaced with older role-registration syntax. Official sources: [subagent configuration](https://learn.chatgpt.com/docs/agent-configuration/subagents) and [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). The configured limit of three excludes the primary orchestrator. Models inherit session settings; no model availability or price assumptions are embedded in the profiles.

All seven TOML files were parsed with Python `tomllib`, and installed Codex `0.164.0-alpha.11.1` accepted `codex --strict-config app-server --print-startup-config` with exit 0. This confirms configuration loading, not that every role was launched in this existing session. A new session may be required to pick up role/config changes. User-profile temporary-directory/PATH warnings were emitted but did not fail the validation.

## Phase 6 integration decisions

- **ADR-041:** The user authorizes a local backend around the selected model despite its rejected monitoring status. Preserve the exact model, preprocessing, threshold and test evidence. API acceptance measures functioning diagnostic software, not detector quality.
- **ADR-042:** Add `diagnostic-1.0.0` for binary historical inference with explicit score/threshold/provenance. Retain canonical event-family v1.0 unchanged; do not fabricate event identities, replay sessions or operational episodes.
- **ADR-043:** Serve only registered train/validation sources; optional sensor payloads must match immutable raw windows. Exclude test/synthetic sources and labels from serving. Persist each prediction and optional diagnostic alert atomically in PostgreSQL with idempotency.

## Phase 7 replay decisions

- **ADR-044:** User authorization adds historical replay using only registered train/validation sources and the unchanged selected model/threshold. The `diagnostic-replay-1.0.0` envelope carries the unchanged diagnostic prediction plus explicit playback/session/sequence metadata. Original diagnostic and event-family schemas retain their identities; no family label or accepted detector is fabricated.
- **ADR-045:** For the local single-worker MVP, run replay scheduling in a dedicated background thread under application lifespan, with PostgreSQL transactional locks/cursors/events authoritative across process restarts. This adapts ADR-003's separate-process plan; inference is outside async HTTP execution, and a separate deployable worker remains deferred. Speed controls delivery pacing only; never skip source rows to catch up.
- **ADR-046:** Use REST for commands and durable SSE for one-way readings/predictions/episode events. PostgreSQL stores event history; reconnect resumes after `(replay_id, sequence)` using Last-Event-ID. At-least-once network delivery requires consumer deduplication. This avoids a bidirectional WebSocket protocol where REST already supplies controls.
- **ADR-047:** Alert episode policy is diagnostic and fixed: first usable score at/above the frozen threshold opens one episode, subsequent positives retain it, a usable negative resolves it, and abstention preserves it. A positive after resolution opens a new episode. Initial positive is left-censored, not proof of onset. No dwell or calibration is fitted; store episode state at prediction time separately from immutable per-prediction status.
- **ADR-048:** Replay starts with an empty causal history at the requested position. Require 60 replayed observations and preserve original endpoint alignment `59+10*k`; no pre-start or future row enters a model window. Original label columns are read only by the separate retrospective demo after replay completion, never by runtime/stream/inference. The demo deliberately retains the model's false positives and missed transient interval.
